# ROS 2 ↔ CM-530 第 17 版：A→B→C 統一整合

本工作區新增 `dual_arm.launch.py`，同時啟動 **一個 CM530 bridge、一個雙臂 MoveIt 規劃場景、一個中央流程管理者**。舊的 A→B、B→C 獨立入口保留供回歸測試；整合運行時只啟動統一入口，不再同時啟動兩個獨立 launch。

`CM530_ROS_BRIDGE-main` 全程唯讀。ROS 軟體、模擬模型、設定及測試全部在該目錄外。沒有燒錄韌體、操作真實馬達或實作 ESP32 通訊。此環境目前未發現 `/dev/ttyUSB*`、`/dev/ttyACM*` 或 `/dev/serial/by-id/*`，實機部分尚不能驗收。

## 整合行為

1. 明確啟動工作後，透過 MoveIt 規劃兩臂回各自的 ROS HOME，並以 CM530 READ 確認關節到位。
2. 在 Home_C 確認 C 八格地圖與紀錄一致，選最小編號空格；C 已滿時不再從 A 取料，保留 B 物件。
3. 如果 B 已有物件，直接執行 B→C。否則 arm1 從 A 取料，返回 Home_A 持物；確認 B 空且無手臂後，由中央管理者保留 B 使用權，進入 B 放料。
4. arm1 回 Home_A，視覺確認 B 有料且手臂已離區，才釋放 B 使用權。
5. arm2 確認 B 有料、C 預定格空，再取得 B 使用權；取料後回 Home_C，確認 B 已空且手臂離區才釋放。
6. arm2 放到指定 C 格，回 Home_C，核對格位與數量後才提交佔用紀錄。
7. `cycles` 指定每次最多搬 1～8 件。預設一件；設 8 可連續填滿。中途錯誤不自動接續。

目前採**兩臂輪流執行**，每段運動完成並確認狀態後才交給另一臂；未宣稱同步起動或同時搬運。共同 URDF／SRDF 保留跨臂碰撞檢查，B 互鎖不能取代規劃場景。Demo 的兩臂安裝位置與停靠姿態只供模擬。

吸盤仍由人員在外部操作 ESP32，再用一次性 token 確認。`auto_confirm_demo:=true` 僅模擬可用，硬體模式拒絕。視覺沿用現有 `vision_interfaces` 的四個服務，沒有修改視覺演算法。

## 建置與執行 Demo

```bash
cd /home/orin/雙手臂
bash scripts/build.sh
source /tmp/dual-arm-ros2/install/setup.bash
ros2 launch dual_arm_control dual_arm.launch.py mode:=demo cycles:=1
```

第二個終端提供統一人工操作介面：

```bash
source /tmp/dual-arm-ros2/install/setup.bash
ros2 run dual_arm_control operator_console --ros-args -p arm:=dual_arm
```

第三個終端啟動與觀察：

```bash
source /tmp/dual-arm-ros2/install/setup.bash
ros2 service call /dual_arm/start std_srvs/srv/Trigger '{}'
ros2 topic echo /dual_arm/status
```

`start.success=true` 只表示接受工作；最終以 `/dual_arm/status` 的 `SUCCEEDED`／`FULL`／`FAULT` 和 `busy=false` 判斷。連續八件模擬可改為：

```bash
ros2 launch dual_arm_control dual_arm.launch.py mode:=demo cycles:=8 auto_confirm_demo:=true
```

故障或 FULL 狀態需要現場確認與復歸，不能連續呼叫 start 略過。統一 launch 的預設 journal 按模式分為 `~/.ros/dual_arm/demo_integrated.json` 與 `~/.ros/dual_arm/hardware_integrated.json`，也可透過 `journal:=/absolute/path/file.json` 指定；請勿讓兩種模式共用同一份紀錄。設定或模型改變時，既有 journal 的指紋不符會鎖定 FAULT。

## 唯讀檢查控制板

先關閉占用相同序列埠的 ROS bridge／手動終端，再執行：

```bash
python3 scripts/cm530_probe.py --port /dev/serial/by-id/實際控制板連結 --output /tmp/cm530-observation.json
```

此工具只發 `VERSION`、`PING`、兩臂 `GET_HOME` 與 `READ`，不發位置、HOLD、torque 或 LED 命令。沒有自動重送。程式輸出包含板上的 HOME 與量測原始位置。

**目前唯讀原始碼的 HOME 是 arm1 `[90,567,712,825]`、arm2 `[590,567,712,825]`，與第 17 版文件的 512 範例不同。** 未確認 HEX/BIN 或實際控制板是否與這份 header 相同，因此板上查詢才是運行時依據。不可將原始位置直接當作 ROS 弧度。

## 實機設定

從 `src/dual_arm_control/config/dual_arm_hardware.yaml` 複製成自己的量測設定，填好：

- 兩臂四關節的零點、方向、raw 限位、rad 限位及 HOME 弧度；arm1 ID 順序 `17,3,2,15`，arm2 為 `12,1,8,16`。
- A 取料範圍與高度、arm1 的 B 放置點、arm2 的 B 取料姿態、C 八格姿態、工具 TCP、物件與障礙物尺寸。
- 量測過的雙臂 URDF／SRDF：兩組 `arm1`、`arm2`，各四個命名關節，固定安裝座標，對應吸盤 TCP。兩臂 B 目標轉到共同模型座標後須在 5 mm 內一致，啟動前會檢查。
- `arm1.calibrated`、`arm2.calibrated`、`arm2.calibration_id`、`hardware_calibrated`，以及明確的 `serial_port`。
- `command_period`、`max_schedule_lag`、`command_timeout`、`position_tolerance`、`stable_count`、`arrival_timeout`：依兩臂混合 AX／READ 的實測延遲設定。硬體不套用 demo 加速倍率。

硬體模板包含 `.nan` 與無效方向等未校正標記；啟動前驗證會拒絕這些值。整合模式由中央協調與共同場景管理另一臂，不要求舊獨立模式的 `standalone_arm1_secured=true`。

```bash
source /tmp/dual-arm-ros2/install/setup.bash
ros2 launch dual_arm_control dual_arm.launch.py \
  mode:=hardware \
  config:=/absolute/path/measured_dual_arm.yaml \
  robot_urdf:=/absolute/path/measured_dual_arm.urdf \
  robot_srdf:=/absolute/path/measured_dual_arm.srdf \
  journal:=/absolute/path/hardware_dual_journal.json
```

此時只握手、查 HOME 和讀位置，不自動啟用 torque。ROS HOME 經量測校正轉換後，必須與板上 `GET_HOME` **完全一致**；否則關閉序列連線並拒絕啟動，避免偷偷使用不同 HOME。

外部安全輸入來源須持續發送 `/safety/estop` (`std_msgs/Bool`)；`true` 鎖定停止，`false` 不能解除已鎖定的狀態，訊息超過設定時效也會中止工作。此 ROS 軟體互鎖不是硬體急停。Demo 才會啟動合成的安全心跳。

確認現場與姿態後，由操作者逐臂明確啟用：

```bash
ros2 service call /cm530/arm1/enable std_srvs/srv/Trigger '{}'
ros2 service call /cm530/arm2/enable std_srvs/srv/Trigger '{}'
ros2 service call /dual_arm/start std_srvs/srv/Trigger '{}'
```

`enable` 的線上順序為 `HOLD → OK → TORQUE,1 → OK → READ`，不使用未知舊目標。後續 HOME 回程由 MoveIt 規劃，再逐點送 AX，不直接用板端 HOME 當作避障路徑。

## ROS 介面

| 名稱 | 類型 | 用途 |
|---|---|---|
| `/dual_arm/start` | `std_srvs/Trigger` | 接受最多 cycles 件的整合工作 |
| `/dual_arm/cancel` | `std_srvs/Trigger` | 停止新增軌跡、取消執行；不代表硬體急停 |
| `/dual_arm/confirm` | `dual_arm_interfaces/ConfirmStep` | 對目前 token 回報吸取、釋放或格位確認 |
| `/dual_arm/recover` | `dual_arm_interfaces/ConfirmStep` | 現場清空後的明確復歸，不發運動命令 |
| `/dual_arm/status` | `std_msgs/String` JSON | 中央狀態、active_arm、holding、b_owner、occupied、slot、token |
| `/arm1/status`、`/arm2/status` | `std_msgs/String` JSON | 該臂工作階段事件；人工確認請使用中央介面 |
| `/handoff/b_state` | `std_msgs/String` JSON | 中央 B 使用權資訊，非獨立節點可自行取得的鎖 |
| `/dual_arm/permit` | `std_msgs/Bool` | 中央管理者存活與允許狀態，bridge 監測時效 |
| `/cm530/status` | `std_msgs/String` | ready／executing／故障原因 |
| `/joint_states` | `sensor_msgs/JointState` | 成功 READ 轉換後的位置與主機時間 |
| `/arm{1,2}_controller/follow_joint_trajectory` | `control_msgs/FollowJointTrajectory` | 四軸規劃軌跡；兩臂共用執行資源 |
| `/cm530/arm{1,2}/enable` | `std_srvs/Trigger` | HOLD 後啟用 torque |
| `/cm530/arm{1,2}/read`、`get_home` | `std_srvs/Trigger` | 成功時 message 為四個 raw 整數的 JSON |
| `/cm530/arm{1,2}/hold`、`disable` | `std_srvs/Trigger` | 明確保持或卸力；busy／通訊失同步時拒絕 |

沒有提供任意文字命令的 ROS topic，避免其他 callback 繞過同一連線管理者。bridge 在任一軌跡執行時拒絕第二條軌跡；所有序列交易受同一把鎖管理，任何時刻最多一筆 pending。

## 協定 5 行為

- USART3：57600、8N1、無流量控制；LF 發送，CR／LF／CRLF 分段接收。每次開埠 `VERSION,5` 再 `PONG`，READY 可能已錯過。
- 精確核對命令、arm、torque／LED 值及資料欄位數、raw 範圍；錯誤回覆也核對手臂、馬達 ID 與 mask。
- `ERR,OVERFLOW`、開機 `ERR,INIT_FAILED`、非預期 READY、逾時、殘留非空資料或錯配使連線失效。不能自動重送、把遲到 ACK 套到下一筆，或在失同步時追加 HOLD。
- 完整匹配的 ERR 代表本筆失敗；上層中止工作。AX／HOME 的 OK 不等於到位；最後一筆 AX 後另外取得多次新 READ，按容差、穩定次數與期限判斷。
- 動作前明確送 LED MOVING；成功確認到位後送 STOPPED。錯誤時不以 STOPPED 宣稱已停止。LED 命令也等待並核對 ACK。
- 程式記錄 TX、RX、monotonic 時間與錯誤。韌體沒有 STOP、DONE、軌跡佇列、斷線自動卸力或 watchdog；本程式不假設有這些功能。

## 取消、故障與復歸

故障會保留 journal 中的工具狀態、B 使用權與已確認的 C 格位，不會清空紀錄後自動重試。取消時若正在執行軌跡，bridge 在連線仍同步的情況下送 HOLD；HOLD 仍只是先讀後寫目標，不能證明瞬間停止。

bridge 執行故障採鎖定方式；處理現場後重啟相關軟體／必要時控制板，重新握手並讀取狀態，不能在未知結果下續送舊軌跡。中央節點重新啟動仍會從 journal 偵測未完成工作，要求復歸。

復歸需要：兩臂工具空、兩臂實測位置符合各自 HOME、B 空且手臂已離區、C 全空且八格視覺確認一致。操作介面會顯示 recovery token；明確確認後清除佔用地圖與使用權，再由使用者重新 start。`FULL` 也走清臺確認，保留 B 的餘料直到現場處理。

## 完整 ROS 原始碼封裝

`releases/dual_arm_ros2_cm530_v17.zip` 包含 ROS packages、雙臂模型、設定、腳本、測試與驗證文件；壓縮檔內有逐檔 `SHA256SUMS`，外部 `releases/SHA256SUMS` 可核對 ZIP 本身。解壓縮後進入 `dual_arm_ros2_cm530_v17`，依上面的 build 指令建置。需要 ROS 2 Jazzy／MoveIt 與既有 Python 依賴，封裝不包含系統套件。

ROS 運行不依賴本機 CM530 原始碼目錄。若要重跑「原版 C parser」虛擬序列測試，請將既有唯讀 `CM530_ROS_BRIDGE-main` 放在解壓後工作區根目錄，維持相同相對路徑；封裝沒有複製或修改該韌體目錄。

重新封裝：`python3 scripts/package_release.py`。
