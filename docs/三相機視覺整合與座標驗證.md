# 三相機視覺接入主控與座標驗證

`scripts/build.sh` 同時建置主控的 `src/vision_interfaces` 鏡像及
`three-camera-vision-ros2-main/vision_pkg`。視覺節點經 ROS 2 service 回報座標：

| 服務 | 主控用途 | 座標系與單位 |
| --- | --- | --- |
| `/vision/env/capture_ranking` | 空批次開始時建立八件物件排序快照 | 不回傳機械手臂座標 |
| `/vision/env/get_zone_state` | 確認 A/B/C 占用及 B 區無手臂 | 不回傳座標 |
| `/vision/arm1/get_pick_target` | 決定 A 區取物中心 | `arm1_base`，公尺；Z 為物件頂面 |
| `/vision/arm2/get_grid_state` | 核對八格占用與放置中心 | `arm2_base`，公尺；Z 為物件頂面 |
| `/vision/arm2/verify_place` | 放置後確認指定格及尺寸順序 | 格位編號 1–8 |

主控在第一次由空的 C 區開始搬運時自動呼叫 `capture_ranking`；失敗或低信心會停在
`FAULT`。後續搬運使用同一快照。手臂 1 的目標座標仍須落在主控設定的 `a_min`/`a_max`
與 `pick_z ± height_tolerance`；手臂 2 的八格座標須與設定的 `c_poses` 各中心差距不超過
`grid_position_tolerance`。任何服務回傳無效或座標不一致，主控停止，不會猜測位置。
視覺端只在手臂停於 Home_A／Home_C 並穩定後才能正確判定，主控已有 `home_settle` 等待。

## 建置與啟動

```bash
cd /home/orin/雙手臂
bash scripts/build.sh
source /tmp/dual-arm-ros2/install/setup.bash
ros2 launch dual_arm_control dual_arm.launch.py mode:=hardware \
  config:=/absolute/path/to/measured_dual_arm_hardware.yaml \
  robot_urdf:=/absolute/path/to/measured.urdf \
  robot_srdf:=/absolute/path/to/measured.srdf \
  env_cam_device:=/dev/v4l/by-id/<env> \
  arm1_cam_device:=/dev/v4l/by-id/<arm1> \
  arm2_cam_device:=/dev/v4l/by-id/<arm2> \
  calib_dir:=/absolute/path/to/vision_calib
```

硬體模式預設啟動三相機；`vision:=false` 可在相機由另一個 ROS 2 行程啟動時使用。
示範模式預設使用假視覺；`mode:=demo vision:=true` 可用真相機與模擬手臂聯調，
但示範幾何必須與視覺座標相符。不要同時啟動假視覺與真視覺服務。

## 首次現場標定

1. 固定三台相機，確認 `ros2 topic hz /env_cam/image_raw`、`/arm1_cam/image_raw`、`/arm2_cam/image_raw` 有新影格。
2. 依視覺套件 README 標定環境站台、A 站平面、手臂 1 與手臂 2 的 homography。手臂 1/2 的標記高度要在物件頂面；相機去畸變設定與標定時一致。
3. 量測 `arm1_base`、`arm2_base`、吸盤 TCP、站台及物件高度，填入硬體設定。尤其要使視覺的 `station_height_mm + object_height_mm` 與主控 `pick_z`／C 格 `c_poses` 的 Z 相符。設定 `a_min`/`a_max` 為實測安全範圍，八格 `c_poses` 與視覺格位順序一致（靠 B 的一排為 1–4）。
4. 在不啟動主控搬運的狀態，先呼叫以下唯讀服務核對回覆。`GetPickTarget` 務必帶 `peek_only: true`；八件物件就位後先拍快照。

```bash
ros2 service call /vision/env/get_zone_state vision_interfaces/srv/GetZoneState '{}'
ros2 service call /vision/env/capture_ranking vision_interfaces/srv/CaptureRanking '{}'
ros2 service call /vision/arm1/get_pick_target vision_interfaces/srv/GetPickTarget '{target_rank: 0, peek_only: true}'
ros2 service call /vision/arm2/get_grid_state vision_interfaces/srv/GetGridState '{}'
```

`get_pick_target` 的 XYZ 是手臂 1 取物接觸目標；`get_grid_state` 的 `place_x/y/z`
依索引 0–7 對應 C1–C8。逐一以低速空載、人工觀察 TCP 對準目標驗證，才允許硬體搬運。
若重啟視覺節點，其記憶體中的排序快照會消失；批次進行中不要重啟環境相機節點。
目前倉庫中的 homography 與硬體 YAML 仍是未實測範本，無法從程式自行推算實機座標。
