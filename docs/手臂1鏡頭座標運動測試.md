# 手臂 1：鏡頭 1 座標運動測試

此測試啟動手臂 1、CM530、MoveIt 與 `arm1_cam`／`arm1_vision_node`。
流程為 **Home_A → 停穩等待 home_settle → 查詢物體座標 → 物體正上方 → 停住**。
到位後不自動返回 Home_A，不下降接觸物體，也不操作吸盤。再次呼叫 start 時才開始新一輪。

主控呼叫 `/vision/arm1/get_pick_target`（`GetPickTarget`），固定傳入
`target_rank: 0`、`peek_only: true`。新版鏡頭不依大小排序，會從畫面中的藍色瓶蓋
依可達範圍、周圍淨空及距離選出目標；畫面可以有多顆瓶蓋。`peek_only` 在新版鏡頭
為相容欄位，不會標記取走；主控不使用 `rank` 決定運動。

回傳 XYZ 的座標系是 `arm1_base`，單位公尺。主控要求 `success=true`、數值有限、
XYZ 在 `a_min/a_max` 內，且 Z 符合 `pick_z ± height_tolerance`。
懸停目標為 **[回傳 X, 回傳 Y, pick_z + approach_height]**。
服務不存在、逾時、無目標、未完成 homography 或座標不合格都回報 `FAULT` 並停止。
保留 `home_settle: 1.1` 秒，讓 Home_A 到位後的影像更新；現場如調整鏡頭逾時與處理頻率，
也須驗證此等待足以淘汰移動中的畫面。

`/arm1/vision_test/start` 接受後，請看 `/arm1/vision_test/status`：
`MOVING_HOME_A → WAITING_FOR_VISION → MOVING_ABOVE_A → SUCCEEDED`。
`target_above_a` 顯示懸停座標；到位後才發布 `SUCCEEDED`，start 回覆只代表接受工作。
執行中重複 start 會被拒絕；cancel 會取消運動並回報 `FAULT`。

## 模擬驗證

```bash
cd /home/orin/雙手臂
bash scripts/build.sh
source /tmp/dual-arm-ros2/install/setup.bash
ros2 launch dual_arm_control arm1.launch.py mode:=demo control:=vision_test
# 另一個終端，載入同一套 setup.bash 後：
ros2 topic echo /arm1/vision_test/status
ros2 service call /arm1/vision_test/start std_srvs/srv/Trigger '{}'
```

建置會將唯讀鏡頭套件複製到 `/tmp/dual-arm-ros2/vision_source/` 後再建置，
避免 Python 或建置工具在鏡頭原始資料夾產生檔案。

模擬模式使用假鏡頭座標與假 CM530。實際鏡頭須先完成 `arm1_homography`
標定，並確認 `/vision/arm1/detections` 的 `base_valid: true`。

## 實機啟動

先實測並填好 `arm1_hardware.yaml` 的 Home_A 關節角、CM530 零位與方向、
吸盤 TCP、A 區界線、取物高度、桌面碰撞模型、序列埠，以及
`calibrated: true`、`hardware_calibrated: true`。`arm1_homography.yaml`
需以手臂 1 在 Home_A 時的物件頂面高度標定。未完成上述量測時，
硬體啟動會被拒絕；不要使用示範座標代替實測值。

```bash
source /tmp/dual-arm-ros2/install/setup.bash
ros2 launch dual_arm_control arm1.launch.py \
  mode:=hardware control:=vision_test \
  config:=/absolute/path/to/measured_arm1_hardware.yaml \
  arm1_cam_device:=/dev/v4l/by-id/<arm1-video-index0> \
  calib_dir:=/absolute/path/to/vision_calib
# 另開終端：
source /tmp/dual-arm-ros2/install/setup.bash
ros2 topic echo /vision/arm1/detections
ros2 service call /cm530/arm1/enable std_srvs/srv/Trigger '{}'
ros2 service call /arm1/vision_test/start std_srvs/srv/Trigger '{}'
ros2 topic echo /arm1/vision_test/status
```

需要中止時呼叫 `/arm1/vision_test/cancel`；實體緊急停止仍須由硬體提供。
目前 Codex 執行沙盒看不到 `/dev/video*` 或 `/dev/v4l/by-id/`；這不代表
主機沒有相機。請在執行相機程式的主機終端查裝置路徑。倉庫的
`arm1_homography.yaml` 仍為 `valid: false`，因此尚無可供實機運動的基座座標。
新版視覺節點偵測藍色瓶蓋；鏡頭專案原始碼維持唯讀，校正檔寫到外部 `calib_dir`。
