單元測試包含：雙臂 ID／欄位核對、版本不符、分段 CRLF、逾時後遲到 ACK、殘留資料、啟動 READY／靜默／不完整資料、錯 arm／ID／mask 的 ERR、OVERFLOW 鎖定、不合法輸出在寫埠前拒絕、四軸校正與限位、軌跡重排與時間驗證、B 鎖競爭、C 最小空格／滿載／格位故障、取消及共同座標中的 B 目標一致性。

串接測試編譯原始唯讀資料夾中的 `APP/src/bridge.c`，使用測試用 Ax12 adapter 與 Linux PTY。實際執行本工作區的 `cm530_bridge` ROS 節點、pyserial、兩臂 `FollowJointTrajectory`、HOLD→TORQUE 啟用、LED 及 READ 監測。驗證第二條同時提交的軌跡被拒絕、每臂終點後至少三筆 READ 才發 STOPPED，以及注入 OVERFLOW 後 enable／hold 不再送線上命令。

完整搬運模擬使用真正 MoveIt IK、路徑規劃、碰撞場景與 ROS actions；只有馬達動態、視覺回覆與人工吸盤操作由模擬器代替。完整流程採雙臂輪流執行，未驗證同步運動。

## 發現並處理

- 將兩個獨立流程改為單一中央管理者、journal、B 使用權與共用序列連線。
- 原單臂示範 Home 同時套用雙臂會阻擋交接路徑；整合 demo 改成朝離開 B 的方向停靠，保留跨臂碰撞檢查，沒有放寬碰撞規則。
- 避免共同 MoveIt 場景中的物件名稱互相覆蓋，兩臂持物／桌面使用各自識別名稱；B 物件在交接時明確轉換場景表示。
- 嚴格處理非同步錯誤、啟動殘留／部分資料，故障鎖定後不再接受新運動；增加串流 TX/RX 與主機 monotonic 時間記錄。
- 啟動時驗證兩臂 B 點落在相同物理位置，硬體模式查詢板上 HOME 並比對校正後的 ROS HOME。

## 限制與待驗收

1. 真實 USB/UART、STM32 中斷時序、DYNAMIXEL 電氣與馬達負載／速度／停止距離尚未測試。環境未發現 USB 序列設備。
2. 實機仍需填寫雙臂量測校正、URDF／SRDF、相機座標與 C 八格資料，確認序列埠與板上協定／HOME，再逐臂低速驗收。
3. ESP32 吸盤仍採既有外部操作＋人工確認，沒有新增或猜測 ESP32 通訊協定。外部真實視覺與安全輸入來源尚待聯調。
4. 取消／故障後的實際保持姿態、人工清臺及復歸，需要實機驗收；本次未把實體復歸流程列為通過。
5. **MoveIt 關閉階段問題：** 測試完成並收到 SIGINT 後，已安裝的 `move_group` 在析構／關閉階段出現 segmentation fault，部分執行需 SIGKILL 收尾。相同現象亦出現在原有獨立 A→B 入口的回歸測試。這不影響先前已核對的任務結果，但關閉不算乾淨；本次未修改系統 MoveIt 套件，需另行排查已安裝版本的關閉問題。

`validation` 中的 `passed=true` 僅表示該測試的行為斷言通過，不代表上述硬體項目或 MoveIt 關閉問題已解決。
